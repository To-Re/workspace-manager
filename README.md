# Workspace Shelf 工作区管理

侧栏顶部只保留一个主按钮：**保存当前窗口**。悬浮在保存、打开和铅笔按钮上可查看作用说明。点击后自动保存当前文件夹、文件标签和工作区设置，并生成名称；想换名字，点记录旁的铅笔即可。

## 使用

打开文件或项目，点击活动栏的“工作区管理”，再点击顶部保存按钮。不需要提前创建工作区文件，不需要选择存放位置。只有两个打开的文件也能保存；不会因为保存文件标签而将它们的整个父目录加到项目中。

点击已保存记录，在新窗口打开；右键可在当前窗口打开或移除。搜索和刷新放在侧栏的更多菜单里。移除只删除列表记录，可以撤销，不删除源码、文件或快照。

同一窗口再次点击保存，会更新记录并保留改过的名称。保存的是点击时的窗口状态，之后新增文件、文件夹或修改配置，需要再次点击保存。未命名的多文件夹工作区保存成功后，会在当前窗口打开生成的工作区文件；窗口会重新加载一次，之后关闭不再提示保存未命名工作区。未保存的文件内容仍由 VS Code 提醒处理。

## 保存和恢复的内容

- 文件夹列表，包括本地和 Remote SSH URI；重新连接仍需要原 SSH 配置和认证，插件不管理密钥。
- 工作区设置、任务、调试配置及扩展推荐。
- 普通文件和笔记本标签的地址、分组列和活动文件；重新打开工作区时恢复。
- 未保存的文本编辑或新文本文件，以草稿快照保存；恢复为新的未命名文档，避免覆盖原文件。

终端进程、Diff、Webview、笔记本内未保存的单元格修改和任意第三方编辑器状态不包含在此版本的快照中。插件改名会生成同名 `.code-workspace` 文件，下次打开使用新名称；固定的 `window.title` 设置仍会覆盖默认标题。原文件夹和用户自行保存的工作区文件保持不变。

## 数据与恢复

数据只写到客户端 VS Code 的插件全局存储目录。`workspaces.json` 保存列表，`managed/` 保存工作区文件和文本草稿快照；没有云同步和遥测。备份时保留整个目录，单独备份列表无法恢复工作区快照。快照可能含未保存的文本内容，请按项目资料保护它。

多个窗口写入使用文件锁和原子替换。切回窗口或从更多菜单刷新，可看到其他窗口的更改。改名、更新和移除保留旧快照，避免破坏仍打开的窗口；本版本不自动清理旧快照。工作区备份不替代项目文件备份。

配置损坏时提示错误并保留原文件。若写入被强制中断后持续提示占用，请先关闭所有 VS Code 窗口，备份存储目录，再只删除 `workspaces.json.lock` 后重新启动。不要删除 `workspaces.json`。

## 开发

Node.js 22 或更新版本，每个插件独立 Git。本项目不依赖同级 ReviewSlate。

```sh
npm ci --ignore-scripts
npm test
mkdir -p artifacts
npm run package
```

F5 启动扩展开发宿主。产物在 `artifacts/`。运行时使用 VS Code API、Node.js 内置模块和 JSONC 解析器，打包使用 VSCE。验收范围与限制见仓库内 `VALIDATION.md`。
