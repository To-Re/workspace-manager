# Workspace Shelf 工作区管理

把常用的本地项目和 SSH 工作区放在一个列表里，自定义名称，重启后继续打开。使用 VS Code 原生侧栏和搜索框，兼容浅色、深色主题与键盘导航。

## 使用

安装后点击活动栏的“工作区管理”。打开一个项目，点击侧栏顶部的加号，输入名称即可收藏。点击记录会在新窗口打开；右键可在当前窗口打开、改名或从列表移除。移除只删除收藏记录，提示中可以撤销，不删除项目文件。

顶部搜索按钮按名称、主机和路径查找。通过“添加已有工作区文件”可收藏已有 `.code-workspace` 文件。未命名的多文件夹工作区只需点击收藏并输入名称，插件就会在自身存储目录保存 `.code-workspace` 快照，保留文件夹、设置、任务、调试配置和扩展推荐，不再要求先手动另存为。当前窗口继续使用原工作区；之后新增文件夹或调整工作区设置，再次收藏即可更新快照。收藏单文件夹不会复制项目配置或未保存的编辑内容；已保存工作区通过其原文件恢复。

SSH 工作区须先正常连接并打开目标文件夹，再收藏。插件保存远程 URI，重新打开交给 VS Code Remote SSH；需要该扩展和可用的 SSH 配置与认证。不会导入密钥或修改 SSH 配置。行内铅笔按钮和右键菜单均可改名。已有项目和用户自行保存的工作区只修改列表名称。插件自动保存的工作区会生成新名称的工作区文件，下次打开显示新工作区名称；自定义的固定 `window.title` 设置仍优先。当前窗口不强制切换。

## 数据与恢复

扩展只在客户端运行。收藏保存在本机扩展全局存储目录的 `workspaces.json`，包含名称和路径，不启用云同步或遥测。多个窗口写入使用锁文件，原子替换；切回窗口或点击刷新可看到其他窗口的更改。

配置损坏时提示错误并保留原文件。若写入被强制中断后持续提示占用，请先关闭所有 VS Code 窗口，备份全局存储目录，然后只删除其中的 `workspaces.json.lock` 再重新启动。不要删除 `workspaces.json`。自动保存的工作区文件位于同一目录的 `managed/` 中。请备份整个扩展存储目录，单独备份 `workspaces.json` 不足以恢复自动保存的工作区。改名或更新快照会保留原文件，避免影响已打开的窗口；移除收藏也不删除这些快照。它们不包含项目源码、SSH 凭证或编辑器里未保存的文件，不能替代项目备份。

## 开发

Node.js 22 或更新版本。每个插件独立 Git，本项目不依赖同级 ReviewSlate。

```sh
npm ci --ignore-scripts
npm test
mkdir -p artifacts
npm run package
```

使用本仓库的 F5 配置可启动扩展开发宿主。安装包在 `artifacts/`。运行时使用 VS Code API、Node.js 内置模块及 JSONC 解析器，打包使用 VSCE。

首版自动测试覆盖重启读取、多个实例并发写入、远程地址隔离、损坏保护、记录修改和当前目标选择。自动测试与构建不代表真实 Remote SSH 端到端或界面操作已完成验收；实际验证见 仓库内的 `VALIDATION.md`。
