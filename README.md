# Workspace Shelf 工作区管理

把常用的本地项目和 SSH 工作区放在一个列表里，自定义名称，重启后继续打开。使用 VS Code 原生侧栏和搜索框，兼容浅色、深色主题与键盘导航。

## 使用

安装后点击活动栏的“工作区管理”。打开一个项目，点击侧栏顶部的加号，输入名称即可收藏。点击记录会在新窗口打开；右键可在当前窗口打开、改名或从列表移除。移除只删除收藏记录，提示中可以撤销，不删除项目文件。

顶部搜索按钮按名称、主机和路径查找。通过“添加已有工作区文件”可收藏已有 `.code-workspace` 文件。未保存的多文件夹工作区请先运行“工作区管理：将当前工作区另存为…”，再收藏。收藏单文件夹不会复制项目配置或未保存的编辑内容；已保存工作区通过其原文件恢复。

SSH 工作区须先正常连接并打开目标文件夹，再收藏。插件保存远程 URI，重新打开交给 VS Code Remote SSH；需要该扩展和可用的 SSH 配置与认证。不会导入密钥或修改 SSH 配置。显示名称只影响收藏列表，不修改文件夹名称或窗口标题。

## 数据与恢复

扩展只在客户端运行。收藏保存在本机扩展全局存储目录的 `workspaces.json`，包含名称和路径，不启用云同步或遥测。多个窗口写入使用锁文件，原子替换；切回窗口或点击刷新可看到其他窗口的更改。

配置损坏时提示错误并保留原文件。若写入被强制中断后持续提示占用，请先关闭所有 VS Code 窗口，备份全局存储目录，然后只删除其中的 `workspaces.json.lock` 再重新启动。不要删除 `workspaces.json`。备份该文件即可保留收藏，但不能替代项目本身的备份。

## 开发

Node.js 22 或更新版本。每个插件独立 Git，本项目不依赖同级 ReviewSlate。

```sh
npm ci --ignore-scripts
npm test
mkdir -p artifacts
npm run package
```

使用本仓库的 F5 配置可启动扩展开发宿主。安装包在 `artifacts/`。运行时只依赖 VS Code API 和 Node.js 内置模块，打包使用 VSCE。

首版自动测试覆盖重启读取、多个实例并发写入、远程地址隔离、损坏保护、记录修改和当前目标选择。自动测试与构建不代表真实 Remote SSH 端到端或界面操作已完成验收；实际验证见 仓库内的 `VALIDATION.md`。
